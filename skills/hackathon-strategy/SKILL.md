# Hackathon strategy

Generate breadth across genuinely different assumptions before converging.
Evaluate rule fit, user value, differentiation, feasibility, time, demoability,
sponsor depth, evidence, and failure risk. High-impact selection should use
independent passes and an adversarial view, then preserve the winner, runner-up,
rationale, evidence, risks, and reconsideration conditions as a decision.

There is no token-minimization objective. Additional reasoning must still be
useful; never create artificial loops or work whose purpose is usage inflation.
